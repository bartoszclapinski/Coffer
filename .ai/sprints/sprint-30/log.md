- `--:--` 30-C complete (import robustness). Identical rows within one file are kept: `TransactionHash.Compute(..., occurrence)` — occurrence 1 is byte-for-byte the legacy hash (pinned by a SHA-256 test and by every golden-file hash), the n-th repeat hashes as `base|#n`; `ImportSummary.WithinFileRepeats` reports them (Import screen shows a muted line). Cross-import dedup unchanged (same file again → 0; a vault that once collapsed the rows only gains the missing repeat; a mid-day export followed by the full-day export adds only the new occurrence). New `CsvTextDecoder` (UTF-8 BOM → UTF-8; strict UTF-8 whose non-ASCII stays in Latin/punctuation/currency ranges → UTF-8; else Windows-1250) used by the detector, the PKO parser and the AI fallback. The plausibility check came from review: Windows-1250 `SPÓŁKA`/`SPÓŁDZIELNIA` bytes are valid UTF-8 and decode to Cyrillic garbage. New golden files: one synthetic diacritics statement in cp1250, UTF-8 and UTF-8+BOM (`-text` in `.gitattributes`); the original golden is untouched. An unexpected CSV layout → `UnsupportedStatementLayoutException` → localized "re-saved in Excel?" message. The import log no longer carries the statement file name. `.gitignore` covers `*.real.*`, `Historia*Rachunku*.csv`, `historia_*.csv`, `Zestawienie*operacji*.csv` and root-level `*.csv`.
- `--:--` 30-C follow-up from the review notes: the PKO parser took any `Nazwa …` sub-field as the merchant, so a tax transfer's `Nazwa i nr identyfikatora:` could become the merchant — now only `Nazwa nadawcy`/`Nazwa odbiorcy` labels count.
